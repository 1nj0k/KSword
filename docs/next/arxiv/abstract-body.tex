Live memory control in nested virtual machines spans independently managed address translations. We present KSword, a VMX monitor that can be inserted beneath a running Windows guest of Hyper-V without rebooting Windows, and then host an unmodified VMware instance and its TinyCore Linux guest. KSword composes extended page tables (EPT) to redirect a selected 4 KiB guest-physical page to private backing. A lease binds the VMM process lifetime and sampled source translation path; removal coordinates CPU invalidation before reclaiming backing. The page-control path uses no intermediate-VMM management API, code hook, or injected component, although guest instrumentation selects and pins the test page. On one machine with four Windows vCPUs and two Linux vCPUs, we validate remapping, rollback, and reclamation, and compare reversible HTTP policy corruption with guest-side direct writing. In five insertions with descendant VMMs absent, median driver-body time is 2.60 ms and the CPU rendezvous envelope is 111.6 microseconds. Across 24 paced TCP observations, 74,145 responses remain valid; the largest command-overlapping completion gap is 6.23 ms, including pacing and scheduling effects. Windows-only benchmarks retain substantial costs: 8.76 times baseline CPUID latency and 30.7\% higher loopback round-trip time. A Hyper-V/TinyCore baseline boots, but KSword admission is refused in the inner Windows root partition where VMX is unavailable. These results establish reversible control of the evaluated pages under the stated assumptions.
