Live memory control in nested virtual machines spans independently managed address translations. We present KSword, a VMX monitor that can be inserted beneath a running Windows guest of Hyper-V without rebooting it, and then host an unmodified VMware instance and its TinyCore Linux guest. KSword composes extended page tables (EPT) to redirect a selected 4 KiB guest-physical page, or a 2 MiB region cloned from it, to private backing. A lease binds the VMM process lifetime and sampled source path; removal coordinates CPU invalidation before reclaiming backing. A region is admitted where the intermediate VMM's leaf is that coarse, or, optionally, after all 512 source entries agree, rechecked by sampling and revoked on drift; 1 GiB is refused here, where that VMM maps at 4 KiB. Replaceable bases follow what the descendant touched, not what it was configured with: at 4 GiB its bulk memory sits above the 4 GiB line. The page-control path uses no intermediate-VMM management API, code hook, or injected component, although guest instrumentation selects and pins the page. On one machine with four Windows vCPUs and two Linux vCPUs, we validate remapping, rollback, and reclamation, and compare reversible HTTP policy corruption with guest-side direct writing. In five insertions with descendant VMMs absent, median driver-body time is 2.60 ms and the CPU rendezvous envelope is 111.6 microseconds. Across 24 paced TCP observations, 74,145 responses remain valid; the largest command-overlapping completion gap is 6.23 ms, including pacing and scheduling. Windows-only benchmarks retain substantial costs: 8.76 times baseline CPUID latency and 30.7\% higher loopback round-trip time. A Hyper-V/TinyCore baseline boots, but KSword admission is refused in the inner Windows root partition where VMX is unavailable. These results establish reversible control of the evaluated pages under the stated assumptions.
